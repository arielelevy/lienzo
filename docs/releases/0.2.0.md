# Lienzo 0.2.0

Envío a Codex mediante `codex queue` y conexión explícita de sesiones de Claude Desktop mediante un
adaptador hijo autenticado. La interfaz distingue aceptación, incertidumbre y entrega; kill/Esc siguen
sin habilitarse para sesiones de escritorio. La versión aparece abajo a la izquierda.

El circuito real API de Lienzo → Claude Desktop → respuesta se verificó con un único mensaje peer,
un único ACK exacto y confirmación final publicada. No se afirma que un `pipe_written` sea entrega.
Conectar una sesión Desktop nueva requiere ejecutar una vez su comando público vigente en esa
conversación. No hace falta autorizar cada mensaje. El arranque automático queda para otro corte;
el prototipo y sus pruebas se conservaron localmente fuera del release.

Se corrigieron resultados tardíos que degradaban entregas, falsas confirmaciones de coordinación,
streams SSE expulsados que seguían emitiendo pings, reservas simultáneas de investigadores, cierre
de SQLite ante errores y preservación de restauraciones ilegibles. Las reglas conservan el estado
del transporte y los traspasos inciertos mantienen el trabajo en origen. Las copias rechazan enlaces
y junctions existentes bajo sus raíces; no se garantiza protección contra sustituciones hostiles
del filesystem entre validación y uso.

El corte incorpora además el trabajo existente de cuotas, catálogo/plugins, evaluación y aprendizaje,
y documentación consolidada. Los documentos intermedios retirados siguen disponibles en Git;
sesiones, transcripciones, informes y prototipos locales no se borran para publicar.

## Validación y límites

- Correcciones de diseño: 367 pruebas backend y 13 UI con código 0.
- Clasificación Desktop y respuestas tardías: 68 pruebas focales y Ruff con código 0.
- Bridge/bootstrap: 8 + 6 pruebas con código 0; entrypoint directo: 1 prueba con código 0.
- Indicador de versión: dos mediciones de disposición; fixture de refresco: un recorrido corregido.
- Cierre: build 0.2.0, ESLint global y cinco archivos de pruebas Node con código 0.
- Vite advierte un chunk mayor de 500 kB; el build termina correctamente.

La corrida global iniciada para este corte se interrumpió a pedido de simplificar el cierre: no tiene
resultado completo y no cuenta como aprobada. Se conserva la evidencia focal anterior. No se fijaron
baselines ni se aprobaron mutaciones; no se declara PASS certificado de aceptación agéntica.

El transporte Claude usa una interfaz interna con autenticación del hijo documentada. Versiones
medidas: 2.1.299 y 2.1.302; no hay garantía para versiones futuras ni sobre restricciones de cuenta.
Los permisos del receptor siguen vigentes. Los rechazos automáticos anteriores se respetaron;
no se agregaron reglas ni se desactivó auto mode.
