# Lienzo 0.4.0

Versión minor pedida por Ariel para recuperar el envío normal a Codex CLI y corregir la continuidad de conexiones y reglas de coordinación.

## Codex CLI

Los mensajes se escriben en la consola visible, con el proceso fijado por PID y fecha de creación. `/new` y `/clear` no requieren inferir el hilo activo a partir de un rollout abierto. Codex Desktop conserva su transporte de cola. Los envíos inciertos no se repiten automáticamente y la confirmación exige un turno nuevo con el mensaje completo.

Las transcripciones se observan por handles del proceso, sin asignarlas por carpeta o cercanía de fecha. Un rollout ambiguo no autoriza envíos a una cola ni permite quitarle su transcripción a otro proceso vivo. El texto fuera del BMP viaja en un adjunto UTF-8 para conservarlo al escribir en la consola.

## Claude por pipe

Las conexiones que ya dieron consentimiento conservan un descriptor público sin credenciales. Tras reiniciar Lienzo, el adaptador verifica la identidad del servidor y recupera el canal mientras siga vivo el mismo proceso Claude. El token de Claude permanece en memoria. El bootstrap fija los ancestros antes de anunciar `ready`; el consentimiento se publica antes del primer poll exitoso. Cerrar explícitamente el enlace cancela esa recuperación.

El comando PowerShell usa `&` y no agrega otro `!` al modo bash. Una instalación que todavía usa el adaptador anterior necesita conectarse una vez con el nuevo. Lanzar con conexión automática sigue siendo opt-in mediante `claude_pipe: true`. Un envío incierto nunca se repite automáticamente.

## Reglas y tarjetas

Las reglas de orígenes muertos sin posibilidad de restauración se archivan con motivo y siguen visibles. Al volver el mismo id se recuperan las reglas estacionadas, conservando las que el usuario había apagado. `cablear()` cuenta solamente reglas activas. `PUT enabled:true` reactiva cuando las puntas están vivas; de lo contrario devuelve 409 explicado.

Las flechas deshabilitadas se dibujan atenuadas y muestran el motivo. El editor permite habilitarlas. Las tarjetas vivas muestran si falta una regla hacia la coordinadora de su repo. `DELETE /rules/<id>` elimina cuando puede; si hay informes pendientes devuelve 409 y explica que los conserva.

Un aviso Codex `sin_enviar` anterior se retira cuando existe un envío posterior confirmado exactamente. La corrección también alcanza tarjetas persistidas sin nuevos cambios en la transcripción. Conserva permisos, preguntas, fallos posteriores y envíos inciertos; no reenvía mensajes.

`/exit` y `/quit` enviados desde el tablero a Codex o Pi devuelven 400 con una indicación explícita de cierre. No se presentan como un cierre del proceso.

## Validación

Backend completo: **2416 pruebas aprobadas y 3 omitidas** en 444,44 s. Las tres omisiones necesitan rollouts de muestra que no están en esta PC. El caso `backend-pytest` del runner terminó con código 0 e igualó su baseline.

Interfaz completa: **201 pruebas Chromium aprobadas y 6 omitidas**. Las seis omisiones son generadores de capturas del README que requieren `CAPTURAS=1`. Lint, unitarias y build: código 0. El runner de frontend conserva código 1 porque no existe su baseline aprobado.

La prueba real de integración usó la Claude CLI abierta por Ariel: un envío por pipe antes del reinicio y otro después. Cada envío produjo exactamente un mensaje peer y un ACK, con recibo `entregado`. El adaptador mantuvo su PID y recuperó el canal sin ejecutar otro bootstrap. El aviso viejo también desapareció de una tarjeta real conservando su recibo.

La continuidad de Claude Desktop se cubre con los contratos del mismo transporte y procesos Windows sintéticos. No se presenta la prueba real de CLI como una ejecución de la app Desktop original.

El recorrido agéntico conserva los cinco roles y los logs. La compuerta específica de estos cambios devuelve 2 por falta de baseline aprobado; las propuestas y mutaciones nuevas no se aceptaron automáticamente. No hay PASS certificado ni una nueva medición de mutaciones.

La [revisión de integración](https://github.com/arielelevy/lienzo/blob/79702b136151492c6cdd3d77dd52a5e5055af27e/code-review-2026-10-18-release.md) conserva los fallos de desarrollo, el timeout inicial y el límite de la inspección instantánea de ancestralidad. La prueba final exige reconexión real en 10 s con el mismo adaptador, validación OS y rechazo de otro proceso. No se relajó la validación de producción.
